CODEX_WEBSITE MODIFICATION GUIDE
================================

This file is the quick reference for updating website text, grammar, images,
projects, and blog articles.

More detailed references:
- CONTENT_GUIDE.md
- docs/COPY_REVIEW_CHECKLIST.md
- docs/GITHUB_PAGES.md


1. WHERE TO MODIFY TEXT
-----------------------

Landing page:
- File: index.html
- Hero introduction starts around line 68.
- Experience/expertise starts around line 115.
- Career path/About summary starts around line 167.
- Blog preview starts around line 200.
- Portfolio starts around line 227.
- Moon Rabbit Lab section starts around line 405.

About page:
- File: about.html
- Main biography starts around line 64.

Project pages:
- Each project has its own HTML file.
- Examples:
  - fea_climbing.html
  - ABC_climbing.html

Navigation and footer text:
- Navigation and footer content is repeated across several HTML files.
- A global wording change must be applied consistently to every page.
- Ask Codex to apply global changes if you want to avoid missing a page.


2. WHERE TO MODIFY BLOG ARTICLES
--------------------------------

Existing articles:
- Folder: content/blog/
- Each article uses this structure:
  content/blog/article-id/index.md

New article template:
- File: content/blog/_template.md

To create an article:
1. Copy content/blog/_template.md.
2. Create content/blog/your-article-id/index.md.
3. Replace the template metadata and article content.
4. Add images under img/blog/your-article-id/.
5. Set status to published when the article is ready.

Do not manually edit data/posts.json. It is automatically generated from the
Markdown article files.


3. WHERE TO MODIFY IMAGES
-------------------------

General website images:
- Folder: img/

Blog images:
- Folder: img/blog/article-id/

Branding and logo guidance:
- File: img/branding/README.md

Blog image guidance:
- File: img/blog/README.md

When replacing an image while keeping its existing filename, verify that the
new image uses a compatible aspect ratio. When changing the filename, update
the corresponding src or heroImage path in the source file.

Always write useful alt text that describes the image and its purpose.


4. FILES THAT SHOULD NOT BE EDITED DIRECTLY
--------------------------------------------

- Do not edit files inside dist/. This folder is recreated during every build.
- Do not edit data/posts.json for article content.
- Do not edit generated files inside node_modules/.


5. GRAMMAR AND WRITING REVIEW
-----------------------------

Use docs/COPY_REVIEW_CHECKLIST.md before publishing.

Check that:
- Sentences are concise and easy to understand.
- Verb tense and capitalization are consistent.
- Company, product, and project names are spelled consistently.
- Headings follow a consistent style.
- Links and button labels clearly describe their destination.
- Image alt text is meaningful.
- Page descriptions and social metadata still match the revised content.


6. LOCAL REVIEW AFTER MODIFICATIONS
-----------------------------------

Open PowerShell and run:

cd C:\Users\desig\Desktop\codex_website\website_master
cmd /c npm run content:validate
cmd /c npm run dev

Open the local website at:
http://localhost:5173/

Check desktop and mobile layouts. Review navigation, links, images, project
pages, blog cards, and full blog articles.

Stop the local server with Ctrl+C when finished.


7. PRODUCTION BUILD CHECK
-------------------------

Before publishing, run:

cmd /c npm run build

The build must complete successfully. The generated production website will
be placed in dist/.


8. PUBLISHING TO GITHUB PAGES
-----------------------------

After reviewing the website locally and completing the production build:

git add .
git commit -m "Improve website copy and grammar"
git push origin main

Pushing to main automatically runs the GitHub Pages deployment workflow.

Current website URL:
https://jesusmarini-spec.github.io/codex_website/

Check the repository Actions tab if deployment fails:
https://github.com/jesusmarini-spec/codex_website/actions

Custom-domain instructions are available in docs/GITHUB_PAGES.md.


9. RECOMMENDED WORKFLOW
-----------------------

1. Update one section or article at a time.
2. Save and review it locally.
3. Check spelling, grammar, links, images, and responsive layout.
4. Run content validation.
5. Run the production build.
6. Commit with a clear description.
7. Push to main.
8. Verify the deployed GitHub Pages website.
