CODEX_WEBSITE MODIFICATION GUIDE
================================

Quick reference for updating website text, images, shared information,
projects, and blog articles.

Detailed references:
- CONTENT_GUIDE.md
- docs/CODEBASE_GUIDE.md
- docs/COPY_REVIEW_CHECKLIST.md
- docs/GITHUB_PAGES.md


1. LANDING, ABOUT, AND PROJECT TEXT
-----------------------------------

Landing page:
- File: index.html
- Search by section id instead of relying on line numbers:
  - id="home" for the hero
  - id="services" for experience
  - id="about" for the career path
  - id="work" for the portfolio
  - id="connect" for Moon Rabbit Lab

About page:
- File: about.html
- Edit the biography inside the section with id="about".

Project pages:
- Each project still has its own HTML file.
- Edit only the project-specific hero, metadata, descriptions, lists, images,
  and video sections in that file.
- Do not replace the comments named shared:analytics, shared:security,
  shared:header, or shared:footer.


2. SHARED WEBSITE INFORMATION
-----------------------------

Contact details, social URLs, analytics id, and repository title:
- File: data/site.json

Navigation:
- File: src/templates/partials/header.html

Footer:
- File: src/templates/partials/footer.html

Security policy:
- File: src/templates/partials/security.html

Analytics markup:
- File: src/templates/partials/analytics.html

These partials are injected into every applicable page by Vite. Do not copy
the complete header or footer back into individual HTML files.


3. COLORS, FONTS, AND LAYOUT
----------------------------

Global colors, typography, and responsive font sizes:
- File: css/tokens.css

Main landing, navigation, project, and responsive styles:
- File: css/style.css

Blog-only styles:
- File: css/blog.css

Legacy Unity and portfolio styles:
- Files: css/port-6.css and css/port-items.css

Prefer changing a variable in css/tokens.css when a color or font size should
change across the entire website.


4. BLOG ARTICLES
----------------

Existing articles:
- Folder: content/blog/
- Structure: content/blog/article-id/index.md

New article template:
- File: content/blog/_template.md

To create an article:
1. Copy content/blog/_template.md.
2. Create content/blog/your-article-id/index.md.
3. Replace the metadata and article content.
4. Add images under img/blog/your-article-id/.
5. Use useful alt text for every image.
6. Set status to published when ready.
7. Run cmd /c npm run content:build.

Do not manually edit data/posts.json. It is generated from the Markdown files.


5. IMAGES, VIDEO, AND OTHER MEDIA
---------------------------------

General media:
- Folder: img/

Blog media:
- Folder: img/blog/article-id/

Branding guidance:
- File: img/branding/README.md

Blog image guidance:
- File: img/blog/README.md

Use compatible aspect ratios when replacing an existing file. If the filename
changes, update the corresponding src, poster, or heroImage reference.

For new assets:
- Prefer lowercase filenames with hyphens.
- Prefer WebP or AVIF for large images.
- Prefer MP4 or WebM instead of large GIF animations.
- Add loading="lazy" to images below the first visible section.

Run cmd /c npm run assets:audit to refresh docs/ASSET_AUDIT.md. The report is
advisory; verify files manually before deleting them.


6. FILES NOT TO EDIT DIRECTLY
-----------------------------

- dist/ because it is recreated during every build.
- data/posts.json because it is generated from blog Markdown.
- node_modules/ because it is managed by npm.
- package-lock.json unless dependencies are intentionally changed through npm.


7. GRAMMAR AND WRITING REVIEW
-----------------------------

Use docs/COPY_REVIEW_CHECKLIST.md before publishing.

Check that:
- Sentences are concise and easy to understand.
- Verb tense and capitalization are consistent.
- Company, product, and project names are spelled consistently.
- Headings follow a consistent style.
- Links and buttons describe their destination.
- Image alt text explains meaningful images.
- Page descriptions and social metadata match revised content.


8. LOCAL REVIEW
---------------

Open PowerShell and run:

cd C:\Users\desig\Desktop\codex_website\website_master
cmd /c npm run content:validate
cmd /c npm run site:validate
cmd /c npm run dev

Open:
http://127.0.0.1:5173/index.html

Always review through Vite. Opening an HTML file directly will not expand the
shared template markers.

Check desktop and mobile layouts, navigation, links, images, project pages,
blog cards, and full articles. Stop the local server with Ctrl+C.


9. PRODUCTION CHECK
-------------------

Before publishing, run:

cmd /c npm run build

The build validates blog content and the website, then creates dist/.


10. PUBLISHING TO GITHUB PAGES
------------------------------

After local review and a successful build, commit and push the changes when
you are ready. A push to main starts the GitHub Pages workflow.

Current website:
https://jesusmarini-spec.github.io/codex_website/

Deployment status:
https://github.com/jesusmarini-spec/codex_website/actions

Custom-domain instructions:
- docs/GITHUB_PAGES.md


11. RECOMMENDED WORKFLOW
------------------------

1. Update one section or article at a time.
2. Save and review through the Vite development server.
3. Check spelling, links, images, and responsive layouts.
4. Run content and site validation.
5. Run the production build.
6. Review the Git diff and asset audit when relevant.
7. Commit with a clear description.
8. Push only when the revision is approved.
9. Verify the deployed GitHub Pages website.
